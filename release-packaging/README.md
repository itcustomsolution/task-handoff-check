# Bounded packaging preparation

This is an unexecuted release-preparation job for task-handoff-check 0.1.1 and delivery-evidence-check 0.2.0. It does not publish packages or establish authentic completion of a handoff. The unchanged prior release-candidate archives are comparison inputs; they are never renamed as stable artifacts.

One public branch push is proposed, with one standard Ubuntu 24 GitHub job and no retry or paid fallback. The job acquires exactly the five official files pinned in `inputs/ACQUISITION.json`. Candidate code runs only after acquisition, in fresh network namespaces with no network interfaces enabled. All package stdout/stderr is bounded and retained only as byte counts and hashes in the receipt. No registry, credential, deployment, cache or artifact-upload action exists.

`bootstrap.py` verifies the complete manifest before privileged use. A root-owned immutable projection supplies controls and public inputs. A separate broker, controller and worker share one capped slice (3 GiB, 64 tasks, 2 CPU equivalents, zero swap); the worker is further capped at 2 GiB, 32 tasks, 1 CPU equivalent and 4 GiB virtual address space. The one backing tmpfs is 1 GiB with 32,768 inodes. UID 10001, empty capabilities, no-new-privileges, exact cgroup membership, namespace changes and mount modes are checked before commands. Per-file writes are limited to 128 MiB.

The original reservation is 600 seconds: acquisition and toolchain admission end by T+180; offline work has at most 300 seconds and ends by T+480; export and cleanup end by T+600. The external witness stops waiting by T+565, reserving at least 35 seconds for cleanup; an independent absolute monotonic T+570 expiry kills the owned slice. A digest-verified workflow always-cleanup mode only reconciles matching ownership, never restarts work and never resets the original deadline. Its own fixed privileged cleanup/readback helpers are separately disclosed control-plane overhead. The broker is inside the slice. A fixed privileged staging/witness program outside that slice has 256 MiB per-process address-space and 5 CPU-second limits, 64 descriptors, an original 600-second wall deadline, and at most one proxy/native helper at a time. Its six initial unit probes, one passive systemd proxy, at most three cleanup helpers and six terminal readbacks are fixed system commands, each limited to 1 CPU second. These are per-process limits, not a shared five-CPU-second claim. The root witness has a finite upper bound of 21 CPU seconds including its sixteen fixed helpers. The unprivileged launcher/sudo and provider agent are separate control-plane overhead. It executes no package code. GitHub's own agent and checkout action are outside the payload caps; these are not whole-VM limits.

The toolchain must pass layout, exact version and prefix admission. Any relocation, acquisition, isolation, command, output or cleanup failure stops the single attempt without fallback. There are four builds total (one sdist and one wheel from that sdist for each tool), two data-only metadata/payload validations (the second after all candidate descendants exit), installation into two fresh consumers, and the six exact CLI cases. The previously passed implementation suites are not repeated or reclassified as checks of newly built bytes.

Only four allowlisted archives, one bounded receipt and positive cleanup evidence are exported as a total stream of at most 8 MiB. `decode.py` requires the exact run ID, commit and manifest digest, verifies ordering, lengths and file hashes, and refuses incomplete streams or missing positive cleanup. It creates a new output directory and never replaces existing evidence. Decoding a valid stream is not registry publication.

The workflow and controls require a separate exact operational approval before the first push/job. No authorization is conferred by these files. Source review is not runtime qualification. This public tree contains only software/control source, exact public examples, public archive comparison inputs and software digests. It contains no private project/session records, account material or personal data.

The acquisition network phase is a fixed, digest-checked downloader rather than a general proxy. It executes only standard-library control source, ignores proxy environment variables, accepts one official GitHub asset redirect without draining its body, and never executes package/toolchain code while network access exists. This is an explicit v5 implementation clarification from the earlier proxy proposal. The privileged staging/witness wait and capped broker arrangement are likewise new v5 source scope requiring exact approval, rather than an assertion that the older 15-second staging exception admitted them.
